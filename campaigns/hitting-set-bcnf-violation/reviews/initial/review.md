## Correctness

**Blocking finding — forward legality.** The fixed question (`campaigns/hitting-set-bcnf-violation/question.md`, `source_definition`) admits an explicit finite universe, with no requirement that its members be `0,...,n-1`. `work/proof.md:3` says arbitrary explicit element names “can be canonicalized by a polynomial relabeling,” but `work/algorithm.py:6-10,21-30` does not perform this relabelling: it names element attributes from the supplied values while its threshold rules refer to `a0,...,a(n-1)`. The missing premise is that the input has already been canonically relabelled; neither `F` nor `G` includes a map back to original members. `work/contract.md:3` imposes that premise, contrary to the fixed source definition.

The reviewer-owned `check_domain.py` runs the actual forward command on `{"universe":[2,4],"family":[[4]],"k":1}`. It exits 1 because the produced FD left sides contain `a0` and `a1`, neither of which is in the target's attribute set. Hence `F(x)` is not a legal target instance. This is a witnessed failure of the first reduction obligation, independently of how a target solver behaves. Repair by indexing each input member by its position throughout construction and mapping selected indices back to original members in recovery, or by implementing an equivalent explicit canonicalization inside both algorithms. Then extend the proof and the injected end-to-end check to noncanonical labels, including one `k<n` case. Do not merely broaden the input contract.

**Canonical-domain audit.** With `U={0,...,n-1}`, the dependencies in `work/algorithm.py:16-31` match `work/proof.md:7-9`. Before `C,D` are both present, only initially selected element attributes can produce `b_j` or threshold attributes; induction on `i` gives `t_{i,j}` exactly when at least `j` of the first `i` elements were selected. Thus `C` appears exactly for a hitting set (or if initially chosen), and the `C,t_{n,k+1}->D` rule suppresses a partial closure when more than `k` elements were selected. The `k>=n` branch correctly omits the threshold, including `n=0`; empty family gives `∅->C`, and an empty family member blocks deriving `C` unless it was initially selected. If either marker is in `X`, any new attribute in `R` completes both markers and then all of `R`; if neither is in `X`, partial closure occurs exactly for a bounded hitting set. This supports every valid `(X,y,z)`, including alternate `y,z`, and NO-SOLUTION in the canonical domain. `extract` (`algorithm.py:35-42`) returns those selected members, validates the cardinality and every family set, and returns NO-SOLUTION on a valid negative target output. Both source and target output sets are nonempty by their explicit NO-SOLUTION semantics. There is no reliance on the finite tests for this general argument.

The stated `O(n²+s+m)` FD count and `O((n²+s+m)log(n+m+2))` bit-size upper bound are polynomial for canonical input; `k<n` ensures `k+1<=n` despite binary encoding. Construction is deterministic, and recovery scans the input and target output in polynomial time, with no oracle call. The proof's `log(n+m)` expression at the zero boundary should use `log(n+m+2)`, a minor notation correction. The all-output theorem follows from the closure classification, while the prepared 121-case/196-output loop and 50-case/75-output Z3 loop in `work/verification.md` provide finite evidence only. I inspected `work/check.py` and `work/verify.py`: both inject actual constructed targets, independently solve for target outputs and validate recovered source answers; both generate only canonical source universes and sample at most three target determinants per instance. I did not repeat their passing suites. The targeted failing domain check is the needed new evidence.

## Novelty and literature, checked 2026-09-23

The closest accessible primary construction is Bernstein and Beeri, *An Algorithmic Approach to Normalization of Relational Database Schemas* (1976), [Part III, §2, Theorem 8, report pp. 55–56, PDF pp. 63–64](https://ia800105.us.archive.org/24/items/technicalreportc73univ/technicalreportc73univ.pdf). I inspected its theorem and proof. Its source asks for **exactly one** chosen element in each family set, with no binary cardinality bound. Pair dependencies force at most one selection per set, incidences derive auxiliary attributes, and a final dependency produces a violation; the converse extracts a set. The present threshold gadget for ordinary at-most-`k` Hitting Set, and its explicit recovery from every valid `(X,y,z)` and NO-SOLUTION, are absent from that theorem. This supports a distinct reproducible construction, not a claim of first discovery.

[Vardi, *Fundamentals of Dependency Theory*, Chapter 5, Theorem 5.9, PDF p. 20](https://www.cs.rice.edu/~vardi/papers/ttcs87.pdf) reproduces the exact-one construction and attributes it to Beeri–Bernstein. [Garey and Johnson, Appendix A4, SR29](https://perso.limos.fr/~palafour/PAPERS/PDF/Garey-Johnson79.pdf) states the same BCNF violation decision predicate but lists a transformation from Vertex Cover; its SR27, not SR29, lists Hitting Set for Additional Key. The upstream [BCNF model issue](https://github.com/CodingThrust/problem-reductions/issues/447) instead lists Hitting Set for SR29. Thus the upstream attribution is not a reliable identification of a bounded construction. These equivalent decision formulations were considered, but none of the inspected theorem text supplies this complete bounded search rule.

The [1979 TODS paper by Beeri and Bernstein, pp. 30–59](https://doi.org/10.1145/320064.320066) confirms BCNF hardness in its accessible abstract, but its full theorem text was inaccessible here; exact construction and witness recovery in that version remain unverified. The literature check therefore cannot establish priority or exhaust all later bounded variants. This limited coverage should remain explicit in the candidate's relation-to-work section. It does not change the fixed question's allowance for a complete reconstruction of a published construction.

## Significance and cost

Once the source-domain defect is repaired, the rule would meet the fixed task's practical contribution: executable instance construction, closure-checkable violation witnesses, recovery of any target output, and a general proof for cardinality-bounded Hitting Set. It makes no new NP-completeness claim and does not assert the stronger 3NF restriction in the older theorem. The dominant construction cost is `Θ(n·min(n,k+1))` threshold attributes and FDs, quadratic in the worst case; this is polynomial but may enlarge real target instances. No runtime or memory measurements are supplied, and the finite solver sizes are small. No question-specific resource requirement makes that overhead a reason to stop.
